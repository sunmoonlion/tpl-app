# Dev → Prod 转换流程

## 准备

- 冻结源码提交和依赖锁文件；
- 通过单元、契约、前后端配对、容器和真实浏览器门禁；
- 记录数据库、对象存储、队列和 Provider 的恢复点；
- 确认生产 profile 仍处于禁用状态。

## 生成候选 release

使用模板 scaffold 传入生产 namespace、正式 Origin、Casdoor namespace、TLS secret 以及三个
镜像 digest，输出新的 bundle。执行 release hash、schema 和策略测试，不编辑生成后的 YAML。

## 预演

依次执行：

1. 配置解析与 plan；
2. Kubernetes server-side dry-run；
3. 外部 Secret key 集合验证；
4. 数据库 migration 预检；
5. NetworkPolicy、TLS、OIDC backchannel 与 Provider 连通性检查。

## 切换

按 prerequisites/secret/network → migration → runtime → ingress 执行。完整 App 和单组件
入口必须使用同一份 bundle，禁止为临时修复维护第二份 YAML。Migration 成功后清除一次性 Job。

## 验收与回滚

同时验收 Admin→Backend 和 Web→Backend，验证真实 Casdoor 登录、权限边界、核心业务、异步任务、
监控告警和故障恢复。回滚必须使用上一份已门禁的不可变 bundle 和镜像 digest；数据库发生不可逆
迁移时只能按已演练的前滚/恢复方案处理，不能只回滚 Deployment。

## 晋级

证据完整后启用 production profile，提交 release 配置、bundle 与证据引用。任何运行时手工
kubectl edit、临时 env 覆盖或 mutable tag 都视为漂移，必须回收到下一正式 release。
