# celeryworker-tpl-admin-backend 创建说明

## 定位

该目录是 `tpl-app` 内置的 Celery Worker 模板实例，服务 `tpl-admin-backend` 的异步任务。

执行 `init.sh <app-name>` 后会变为：

```text
celeryworker-<app-name>-admin-backend
```

完整用法见 [`../tpl-admin-backend/docs/CELERY.md`](../tpl-admin-backend/docs/CELERY.md)。

## 配置关系

- Worker 默认镜像：`harbor.sunmoonai.com:30443/k8s-images/tpl-admin-backend:1.0.0`
- 业务配置来源：`tpl-admin-backend-config`、`tpl-admin-backend-secret`
- Worker 自身配置：`celeryworker-tpl-admin-backend-config`、`celeryworker-tpl-admin-backend-secret`
- 队列：`tpl.admin.default`

`init.sh` 会把文件内容和路径中的 `tpl` 一并替换成目标应用名。

数据库、Neo4j、Redis 等业务连接不在 Worker 中重新维护，继续复用 `tpl-admin-backend` 的 ConfigMap/Secret。

## Celery broker（方案 D）

应用层**只读** `CELERY_BROKER_URL`，不识别 `RABBITMQ_PRODUCER_URL`。

| Secret | `CELERY_BROKER_URL` 账号 | 挂载到 |
|--------|--------------------------|--------|
| `tpl-admin-backend-secret` | producer（仅 publish） | API；Worker 也会先加载 |
| `celeryworker-tpl-admin-backend-secret` | worker（consume） | 仅 Worker；**覆盖**上者 |

Worker Pod 的 `envFrom` 中 celeryworker Secret 位于 admin-backend Secret **之后**，因此运行时生效的是 worker 账号。

## RabbitMQ

RabbitMQ vhost、用户、权限和队列由 `messaging-platform/rabbitmq` 的 app definitions 统一创建；Worker 使用 worker 用户连接并消费 `CELERY_QUEUE`。
