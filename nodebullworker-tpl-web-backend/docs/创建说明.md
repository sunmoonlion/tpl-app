# nodebullworker-tpl-web-backend 创建说明

## 定位

该目录是 `tpl-app` 内置的 Node Bull Worker 模板实例，服务 `tpl-web-backend` 的异步任务。

当前 `web-backend` 是 Node.js 技术栈，Worker 使用同一个 web-backend 镜像，通过 `node dist/worker` 启动 Nest application context，并消费 Bull 队列。

执行 `init.sh <app-name>` 后会变为：

```text
nodebullworker-<app-name>-web-backend
```

## 配置关系

- Worker 默认镜像：`harbor.sunmoonai.com:30443/k8s-images/tpl-web-backend:1.0.0`
- 业务配置来源：`tpl-web-backend-config`、`tpl-web-backend-secret`
- Worker 自身配置：`nodebullworker-tpl-web-backend-config`、`nodebullworker-tpl-web-backend-secret`
- Bull 队列：`scheduled-tasks`

`init.sh` 会把文件内容和路径中的 `tpl` 一并替换成目标应用名。

数据库、Neo4j、Redis 等业务连接不在 Worker 中重新维护，继续复用 `tpl-web-backend` 的 ConfigMap/Secret。

## 队列

`web-backend` 当前使用 NestJS Bull + Redis。Worker 复用 backend 的 ConfigMap/Secret 获取业务数据库等配置，同时额外挂载 `*-nodebull-redis-conn` 获取 `QUEUE_REDIS_*` 队列 Redis 配置，并在启动时设置 `QUEUE_ON=true` 来注册队列消费者。RabbitMQ 配置不参与该 Node Worker 的运行。
